## 1. Summary of findings that drive the design

1. **The governor never reads battery current.** No current accessor is called in `flight_governor.c`. The only power input
   is the battery voltage, and only for voltage compensation (`flight_governor.c:490-509`). Battery current is optional
   identification evidence for the twin's motor/battery model, never a governor input.
2. **Voltage compensation is inactive whenever the voltage comes from the ESC**: `useVoltageComp = flag && source == ADC &&
   ELECTRIC` (`flight_governor.c:1556`). Fireball: `battery_meter = ESC`, so `gov_use_voltage_comp` has no effect even if ON.
   On both helicopters `motor[0] = clamp(govSum, min, max)` within 1 count on 1.47 M (Fireball) and 1.40 M (Gaui) ACTIVE
   frames, so `gv = 1` in every logged flight.
3. **The compiled `controller.wasm` executes the complete governor** (all modes, state machine, timers, PID, FF, TTA, K
   estimate, recovery init, fallback, bypass, voltage compensation). Replayed from the first frame of a log with the logged
   headspeed, stick, voltage, setpoint and gyro, it reproduces the logged state on 99.975-99.992 % of frames (every
   difference is a one-frame transition offset) and `motor[0]` to 0.41-1.94 permille RMS in ACTIVE (section 10.4).
4. **Most governor parameters are identifiable from the log alone** (no CLI dump): timing parameters from throttle ramps to
   +-0.1 %, the RPM filter from the identity `govP = 1000 K Kp (T - H)/Hf`, the FF weights, curve and FF filter from
   `govF` to the integer (Gaui: no dump, weights 50/10/10 -> yaw 30, 40, 80 over the session), timeouts from state durations,
   fallback drop/precomp from the FALLBACK throttle. Section 11 has the numbers.
5. **The header does not record the timing parameters, and they changed inside the 2026-10-05 Fireball dump.** Ramps give
   gov_startup_time 200 -> 100, gov_spoolup_time 100 -> 80 (between logs 8 and 9, 0-based) and gov_spooldown_time
   200, 600, 100, 75, 50, 80 over logs 0-10. Only logs 10-15 agree with the CLI dump of 2026-10-13.
6. **Power limit (Fireball).** In ACTIVE, headspeed per unit throttle is 245 +- 4 RPM/V (Vbat 22-24.5 V, 4500 RPM). 4500 RPM
   needs 0.82 throttle at 22.5 V and 0.85 at 21.5 V before any load step; the throttle is at 100 % for 1.9-6.3 s and at
   >= 95 % for 3.4-11.4 s in each long flight. Gaui: 150 RPM/V, never >= 95 %.
7. **All three Fireball FALLBACK events happened at 100 % throttle** and were triggered by an RPM glitch (logged jump
   1051-1316 RPM, firmware glitch threshold 1125 RPM at 4500 RPM). FALLBACK throttle is exactly `0.9 x govI` (precomp OFF,
   drop 10 %): 1000 -> 688/672/719. RECOVERY then restarts at `min(T/Kmot, H/R)` = 649/555/521 permille and ramps at
   0.5 /s; headspeed sags 894-1953 RPM (20-43 %) and stays under the request: ACTIVE again after 0.68-1.07 s, within 1 % of the request 0.41-3.14 s later.
8. **Spool-up overshoot (Fireball)** is 7.1 % with gov_spoolup_time 100 and 12.9-13.2 % with 80 (3500 RPM, exit throttle
   0.72 vs 0.85). Gaui: 0.3-1.7 %.
9. **WASM-boundary defects to fix before a governor twin uses the native code** (section 10.3): CLI `battery_cell_count = 0`
   (auto, Fireball) is rejected by the schema; CLI `battery_meter` is not mapped to schema `voltage_meter` (unknown ->
   diagnostic default ADC, which would wrongly enable voltage compensation); CLI `gov_mode = OFF` is not mapped; the
   module has one PID profile (no in-log profile change); `Kmot` restarts at 0; the replay feeds the filtered, logged
   headspeed instead of the raw RPM, so RPM glitches that cause FALLBACK are not reproduced.

## 2. Execution context

- `governorUpdate()` runs inside `mixerUpdate()` (`flight_mixer.c:542`), after the PID controller and after the mixer
  computed stabilized collective and cyclic (`flight_mixer.c:532-539`), once per PID loop. Loop order
  `fw:src/main/fc/core.c:885-897`: setpoint, PID, mixer (governor), motors (`motorUpdate` writes the output and *then*
  reads the RPM sensors), filters (`freqUpdate`), blackbox. The governor at loop k therefore uses the raw RPM read in loop
  k-1, and the blackbox logs this loop's governor output with this loop's (newer) RPM.
- `dT = pidGetDT()` = PID looptime (`flight_pid.c:550`); all governor filters run at `gyro.targetRateHz` = PID rate.
  Fireball: looptime 500 us x pid_process_denom 2 = 1 kHz PID, logged every loop. Gaui: 250 x 2 = 2 kHz PID, logged every
  second loop (`P interval:2`).
- Slew rates are per loop with nominal `dT` (`flight_governor.c:1603-1609`); state timers use `millis()` (real time,
  `flight_governor.c:405-408`).
- Init: `governorInit` at boot (`fw:src/main/fc/init.c:799`, `flight_governor.c:1611-1673`); `governorInitProfile` at boot
  and at every PID profile change (`fw:src/main/flight/pid.c:709`) and MSP write (`fw:src/main/msp/msp.c:3040`).
  `Kmot`, the filters and the state persist across arms and profile changes; only `governorInit` resets them.
- ELECTRIC and NITRO need a *fast* RPM source on motor 0 (frequency sensor or DShot telemetry,
  `fw:src/main/flight/motors.c:184-187`); otherwise arming is disabled and the mode becomes NONE (`flight_governor.c:1627-1633`).
  ESC-telemetry RPM is not accepted.

## 4. Outputs and their consumers

- `u` -> `mixer.input[STABILIZED_THROTTLE]` (limited to `mixer input ST` min/max, `flight_mixer.c:182-202, 545`) -> motor 0
  = ST x rate/1000 (`flight_mixer.c:420, 480`) -> `motorOutput = clamp(.., -1, 1)` (`motors.c:294-297`) -> PWM pulse
  `min_throttle + u (max_throttle - min_throttle)` us, or `min_command` at 0 (`fw:src/main/drivers/pwm_output.c:126-141`), or
  DShot 48..2047 (`fw:src/main/drivers/dshot.c:50-64`). Fireball: PWM 250 Hz, 1100-1940 us; Gaui: PWM 250 Hz, 1070-2000 us.
- `getSpoolUpRatio()` (`flight_governor.c:293-324`): PID yaw precompensation master gain (`flight_pid.c:886`) and TTA.
  ELECTRIC/NITRO: 0 in OFF/HOLD/IDLE/AUTOROTATION, 1 in ACTIVE/FALLBACK/BYPASS, `requestRatio = H/R` in SPOOLUP/RECOVERY/BAILOUT.
- `isSpooledUp()` (`flight_governor.c:326-357`): airborne detection (`fw:src/main/flight/airborne.c:97,110`), PID error decay
  ground/air choice (`flight_pid.c:1313, 1655`), motorized tail start. True in ACTIVE/AUTOROTATION/BAILOUT/BYPASS;
  `u > 0.333` in SPOOLUP/RECOVERY/FALLBACK; false otherwise.
- `getFullHeadSpeedRatio()` = H/Hf in the running states (`flight_governor.c:271-291`): gyro dynamic LPF cutoff
  (`fw:src/main/sensors/gyro.c:471`).
- `getTTAIncrease()`: collective reduction `coll / (1 + ttaAdd x swash_tta_precomp/100)^2` (`flight_mixer.c:330-338`).
- `getGovernorState()`: blackbox event, telemetry.

## 5. Every-loop data update `govDataUpdate()` (`flight_governor.c:567-631`, governed and DIRECT modes)

1. Throttle input (`flight_governor.c:429-463`): `in = getThrottle()`, `off = isThrottleOff()`.
   - NORMAL: as is.
   - SWITCH (ELECTRIC/NITRO only, `flight_governor.c:1490-1494`): if not off and `in > handover`: `R = max(in x Hf, 100)`,
     `in = 1` (the stick sets the headspeed request).
   - FUNCTION: if not off: `in < 0.333 -> idleThrottle`, `in < 0.666 -> autoThrottle`, else `maxThrottle` (profile).
2. `raw = getMotorRawRPMf(0)`; `H = PT2(raw, gov_rpm_filter) x gear`; `ratio = H/Hf` (`flight_governor.c:573-582`).
3. RPM quality (`flight_governor.c:584-606`):
   - `rpmError = (ratio < 0.01 || raw < 10) && u_prev > 0.10`;
   - `rpmGlitch = |raw - PT2(raw)| > 0.25 Hf/gear || raw > 2 Hf/gear` (thresholds set in `governorInitProfile`,
     `flight_governor.c:1596-1597`);
   - `rpmGood` = no error, no glitch, no forced fallback, `raw > 0`, `ratio > 0.05`, all continuously for more than 200 ms.
4. `requestRatio = rpmGood ? H/R : 0` (DIRECT: `u/in`) (`flight_governor.c:609-612`).
5. `gv = govCalcVoltCompGain()` (`flight_governor.c:490-509`): 1, or if active and `Vnom = cells x 3.70 > 2` and
   `Vraw > 2`: `clamp(Vnom / PT2(Vraw, gov_pwr_filter), 0.80, 1.20)`.
6. `ttaAdd = govCalcTTA()` (`flight_governor.c:511-534`, section 6.8).
7. `e = (T_prev - H)/Hf + ttaAdd` (T from the previous loop); `de = dif(e)` (bilinear differentiator with first-order
   low-pass at gov_d_filter/10 Hz; cutoff 0 gives a = b = 0, so D = 0, `common_filter.c:449-472`).
8. `P = K Kp e`, `C = K Ki e dT`, `D = K Kd de`, `F = PT2(K Kf (wc |coll|^(curve/10) + wcyc cyclic + wy |yaw|), gov_ff_filter)`
   (`flight_governor.c:465-488, 621-630`). `|coll|^x` uses `pow_approx` (`common_maths.c:294`).
   Gains: `K = gain/100`, `Kp = p_gain/10`, `Ki = i_gain/10`, `Kd = d_gain/1000`, `Kf = f_gain/100` (`flight_governor.c:1559-1563`).

PT2 (`common_filter.c:168-203`): two equal PT1 stages, each with cutoff 1.553774 fc (so -3 dB at fc), low-frequency
delay `2/(2 pi 1.553774 fc)` = 20.5 ms at 10 Hz, 41 ms at 5 Hz. Cutoff 0 = pass-through (`common_filter.c:122-135`).

## 6. Control law by state

Slew helper (`flight_governor.c:633-650`, used by IDLE, HOLD, AUTOROTATION, RECOVERY, BAILOUT):
`off -> T = 0, u = 0; else u = slewUpDown(u, clamp(in, lo, hi), up, down), T = H`.
Rates `r_x = 10 dT / clamp(time_x, 1, 600)` per loop (full scale 0 -> 1 in `time_x/10` s); `time_x = 0` gives rate 0 =
no limit (`flight_governor.c:1603-1609`, `common_maths.h:235-274`).

### 6.1 State machine, ELECTRIC and NITRO (`flight_governor.c:1090-1254`; throttle laws `1042-1076`)

Each loop: disarmed -> OFF; else `BOXGOVBYPASS && in > handover` -> BYPASS; else the state's own rules in this order
(first match wins). Every state change sets `stateEntryTime`, `stateResetReq = true`, `pidSpoolupActive = false`,
`bypassActive = false` (`flight_governor.c:394-403`). `->X*` = enter X with `govRecoveryInit` (section 6.5).

| # | State | Exits (in order) | Throttle and target in the state |
|---|---|---|---|
| 0 | OFF | not off -> IDLE | u = 0, T = 0 |
| 1 | IDLE | off -> OFF; `in > handover && rpmGood` -> SPOOLUP | slew to `clamp(in, idle, handover)`, up r_startup, down r_spooldown; T = H |
| 5 | THROTTLE_HOLD | `in > handover && rpmGood` -> RECOVERY*; after `hold_timeout`: off -> OFF else IDLE | as IDLE |
| 2 | SPOOLUP | off -> OFF; `in < handover` -> IDLE; `!rpmGood` -> IDLE; `H > 0.99 R` or `u > 0.95 max` -> ACTIVE | 6.2 |
| 4 | ACTIVE | off -> HOLD; `in < handover`: autorotation -> AUTOROTATION else HOLD; `!rpmGood` -> FALLBACK | 6.3 |
| 6 | FALLBACK | off -> HOLD; `in < handover`: AUTOROTATION or HOLD; `rpmGood` -> RECOVERY* | 6.4 |
| 3 | RECOVERY | off -> HOLD; `in < handover` -> IDLE; `!rpmGood` -> IDLE; `H > 0.99 R` or `u > 0.95 max` -> ACTIVE | slew to `clamp(in, idle, max)`, r_recovery both ways; T = H |
| 7 | AUTOROTATION | off -> OFF; `in > handover && rpmGood` -> BAILOUT*; `in < auto` -> IDLE; after `autorotation_timeout` -> IDLE | slew to `clamp(in, auto, handover)`, up r_recovery, down r_spooldown; T = H |
| 8 | BAILOUT | off -> HOLD; `in < handover` -> AUTOROTATION; `!rpmGood` -> AUTOROTATION; `H > 0.99 R` or `u > 0.95 max` -> ACTIVE | as RECOVERY |
| 9 | BYPASS | (when bypass ends) off -> OFF; `in > handover && rpmGood` -> RECOVERY*; else IDLE | 6.6 |

"autorotation" = `gov_autorotation_timeout > 0 && in >= autoThrottle` (`flight_governor.c:389-392`). With FUNCTION throttle
the middle position gives `in = auto` exactly, so it always enters AUTOROTATION when the timeout is not 0; if
`idle == auto` (both helicopters: 0), the low not-off position does too. Timers: `hold_timeout x 100 ms`,
`autorotation_timeout x 1000 ms`, compared with `>` (`flight_governor.c:1650-1651`). State numbers are the logged values
(`flight_governor.h:27-38`).

### 6.2 SPOOLUP (`govSpoolupControl`, `flight_governor.c:875-930`; limits idle .. max_throttle, rate r_spoolup)

- Without PID spool-up: `u = slew(u, clamp(in, idle, max), r_spoolup)` (symmetric), `T = H`. If `gov_use_pid_spoolup` and
  `in > handover` and `u > handover`: switch to PID mode (`pidSpoolupActive`, reset request).
- PID mode: clamp P, I, D; on reset `I = u - (P + D)`; `S = P + I + C + D` (no F, no gv); integrate C unless saturated
  against [idle, max]; `u = clamp(S, idle, max)`; `T = slew(T, R, max(Hf, Kmot) x r_spoolup)`.
- Both: `govMotorConstantUpdate()`.

### 6.3 ACTIVE (`govPIDControl`, `flight_governor.c:932-977`; limits min_throttle .. max_throttle, rate r_tracking)

```
P = clamp(P, -pLim, pLim); I = clamp(I, -iLim, iLim); D = clamp(D, -dLim, dLim); F = clamp(F, 0, fLim)
if GOV SUSPEND:        P = C = D = 0                         (I frozen, F kept)
elif stateResetReq:    I = u_prev/gv - (P + D + F)           (bumpless, once)
S  = P + I + C + D + F                                        (logged govSum)
u* = S x gv
m  = min_throttle/100; if dyn-min active and rpmGood and Kmot > Hf: m = max(m, dyn_min/100 x T/Kmot)
if (u* > m or C > 0) and (u* < max or C < 0):  I += C          (conditional integration)
u  = clamp(u*, m, max_throttle/100)
T  = slew(T, R, max(Hf, Kmot) x r_tracking)
govMotorConstantUpdate()
```
Limits: `pLim = p_limit/100`, etc.; `fLim >= F >= 0` (`flight_governor.c:1565-1573`). The I clamp is applied before the
integration, so I can exceed iLim by one C until the next loop.

### 6.4 FALLBACK (`govFallbackControl`, `flight_governor.c:979-995`)

`F = fallback_precomp ? clamp(F, 0, fLim) : 0`; `S = I + F`; `u = clamp(S x gv x (1 - fallback_drop/100), min, max)`.
I is frozen at its value at entry; there is no slew limit and no target update (`T` keeps its value).

### 6.5 RECOVERY/BAILOUT entry (`govRecoveryInit`, `flight_governor.c:997-1010`)

`T = H`; ELECTRIC only: if `rpmGood && H/Hf > 0.2 && Kmot > Hf`: `u = min(T/Kmot, requestRatio)` with `requestRatio = H/R`.
This is the throttle that holds the present (possibly sagged) headspeed, not the request. NITRO keeps `u`.

### 6.6 BYPASS (`govThrottleBypass`, `flight_governor.c:1012-1040`)

`u` = 9-point curve `gov_bypass_throttle[i]/200` over the collective *stick* `x = (getRcDeflection(COLL)+1) x 4`, linear
interpolation, clamped to [max(idle, 1e-6), max_throttle] (`flight_governor.c:411-427`); slewed at r_recovery until it
reaches the curve, then follows it directly; `T = H`.

### 6.7 Motor constant `Kmot` (`flight_governor.c:550-565`)

ELECTRIC, in SPOOLUP and ACTIVE only, when `rpmGood && u > 0.20 && H/Hf > 0.20`: `Kmot = EWMA(H/u)` with cutoff 0.05 Hz
(weight W = (0.05 + fs/2 pi)/0.05 = 3184 samples at 1 kHz, 6367 at 2 kHz; cumulative mean for the first W samples,
`common_filter.c:251-297`). Used for the target ramp rate `max(Hf, Kmot) x rate`, dynamic minimum throttle and recovery
init. Fireball `Kmot` = 5.4-5.6 k RPM, Gaui 3.4-3.6 k RPM at the end of flights (section 11.6).

### 6.8 Tail torque assist (`govInitTTA`, `flight_governor.c:1523-1541`; `govCalcTTA`, `511-534`)

Active in DIRECT and ELECTRIC when `tta_gain > 0 && tta_limit > 0`. `ttaGain = sign(main_rotor_dir) x tta_gain/(-125)`,
divided by `K Kp` in ELECTRIC. `TTA = PT2(yaw, gov_tta_filter) x spoolUpRatio x ttaGain`; `ttaAdd = clamp(TTA, 0, headroom)`,
headroom DIRECT = `tta_limit/100`, ELECTRIC = `2 max(1 + tta_limit/100 - H/Hf, 0)`. ELECTRIC adds ttaAdd to the error:
the P path gives `+tta_gain/125 x |yaw|` throttle for the torque-increasing yaw direction, and the integrator raises the
headspeed until `H/Hf -> 1 + tta_limit/100`.

### 6.9 DIRECT, LIMIT, NONE

- DIRECT (`flight_governor.c:674-866`): same data update; state machine without rpmGood conditions; SPOOLUP/RECOVERY/BAILOUT
  -> ACTIVE when `u >= in && in >= min_throttle`; ACTIVE = `slew(clamp(in, min, max), r_tracking)` then, with TTA,
  `throttle += throttle + throttle x ttaAdd` (as written: `(2 + ttaAdd) x throttle`, capped at max, `flight_governor.c:685-690`);
  FALLBACK returns to ACTIVE.
- LIMIT: `u = off ? 0 : clamp(in, max(idle, min), max)` (`flight_governor.c:659-665`); no state machine, no events, no
  governor fields computed.
- NONE: `u = getThrottle()` (`flight_governor.c:1455-1457`).

### 6.10 Configuration validation (`flight_governor.c:1468-1521`)

`handover` in [10, 100]; `idle` in [0, min(10 handover - 1, 250)]; `auto` in [idle, same max]; `max_throttle` in
[handover, 100]; `min_throttle` in [10, max_throttle]; SWITCH -> NORMAL and all four flags cleared when the mode is below
ELECTRIC; `fallback_drop` constrained to [0, 50] and `headspeed` to [100, 50000] at use.

### 6.11 In-flight adjustments (`fw:src/main/fc/rc_adjustments.c:223-236`, setters `flight_governor.c:1266-1425`)

GOV_GAIN, P/I/D/F gains, TTA gain, yaw/cyclic/collective FF weight, idle and auto throttle, max and min throttle and
headspeed can change in flight (event INFLIGHT_ADJUSTMENT). Side effects as written: a headspeed adjustment does not
recompute the glitch thresholds; a gain or P-gain adjustment does not renormalize the ELECTRIC TTA gain.

## 10. The WASM build

### 10.1 What executes

`build.cjs:27-42` compiles the unmodified `flight_governor.c` (hash-checked, `manifest.json`) with `governorInit`,

### 10.3 Defects and gaps at the boundary (verified with `fromHeader` and `compatibility`)

1. `battery_cell_count`: schema range [1, 24], default 6 (`schema.cjs:20`). CLI 0 means auto-detect
   (`fw:src/main/sensors/battery.c:322-336`); `fromHeader({}, {battery_cell_count: 0})` gives "The flight controller value is
   out of its range: battery_cell_count." and `create()` throws (`firmware_controller.cjs:141, 171`). The Fireball dump has 0.
   The firmware value is the detected count (6 for the Fireball); the boundary has no auto rule.
2. CLI `battery_meter` is not read: the schema field is `voltage_meter` (`schema.cjs:21`) and `fromHeader` has no alias
   (`firmware_controller.cjs:56-66`), so the source stays unknown and diagnostic execution uses 1 = ADC. With
   `gov_use_voltage_comp = ON` and `battery_meter = ESC`, the WASM would apply a compensation that the firmware never
   applies (`flight_governor.c:1556`). FBUS (3) is out of the schema range [0, 2].
3. CLI `gov_mode = OFF` (the firmware lookup name, `settings.c:474-476`) is not in the enum map `{NONE, LIMIT, ...}`
   (`firmware_controller.cjs:55`), so it becomes unknown.
4. One PID profile only (`host.c:21-23`): a profile change inside a log (`fw:src/main/flight/pid.c:709`) cannot be replayed;
   Gaui log 38 matches to 17.9 s and then diverges (throttle RMS 444 permille) at the 2300 -> 2500 switch. A bridge export that
   writes `profile.governor` and calls `fw_governorInitProfile` would match the firmware.
5. `rf_reset` zeroes `gov` (`bridge.c:7`): Kmot restarts at 0 each replay, while the firmware keeps it from boot. Kmot
   sets the target ramp rate, the recovery init throttle and the dynamic floor.
6. Using the logged headspeed as raw RPM pre-filters the glitches: the FALLBACK at Fireball log 11, 54.334 s has a logged
   jump of 1051 RPM, under the 1125 RPM threshold, so a replay does not enter FALLBACK. It also shifts transitions by
   about one frame (10.4).
7. Mode switches (bypass, suspend, forced fallback) are not passed although the log records them.
8. `isMotorFastRpmSourceActive` is stubbed true (`host.c:53`): the WASM runs a governor that the firmware would disable
   with an ESC-telemetry RPM source.
